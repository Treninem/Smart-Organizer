# Smart Organizer — правила для всех работников и ИИ-агентов

> **ОБЯЗАТЕЛЬНО.** Эти правила действуют для Codex, ChatGPT Work, других чатов, локальных и облачных работников. Перед каждым изменением читать этот файл, README.md и **docs/PROJECT_MASTER_LOG.md**.

## Каноническая координация

- Один **единый журнал задач/действий для разработчиков**: docs/PROJECT_MASTER_LOG.md. Не путать с локальным SQLite-журналом операций пользователя, который содержит обратимые перемещения и никогда не публикуется.
- Проверять реальное состояние исходников, открытых PR, HEAD и CI: запись в журнале не является доказательством готовности.
- Перед редактированием объявить в таблице CLAIM запись: код задачи, исполнитель (например, Codex-Windows-1), UTC-время, ветка, конкретные файлы, статус ACTIVE. Не занимать файлы чужого ACTIVE CLAIM.
- Другой работник может вести непересекающиеся файлы в отдельной ветке. При конфликте выбрать независимый модуль/тест или дождаться освобождения CLAIM; запрещены force-push, сброс и перезапись чужих изменений.
- После завершения CLAIM перевести в DONE/BLOCKED, указать commit/PR и результаты **реально проведённых** тестов. Зависшие претензии нельзя стирать: отметить STALE с объяснением и перепроверкой GitHub.
- Не менять main напрямую: изменения → отдельная ветка → проверяемый PR → CI → код-ревью → merge.
- Если архитектуру нужно менять, зафиксировать в журнале выбор, компромиссы и критерии проверки до реализации.

## Безусловные требования безопасности

- Приложение Windows должно оставаться рабочим, отзывчивым и запускаемым при сбое отдельных расширений.
- data/, logs/, локальная knowledge.db, персональная конфигурация и любые пользовательские файлы не коммитятся, не удаляются установщиком и не отправляются в облако.
- Нет автоматического удаления программ, реестра, системных служб, драйверов, файлов или папок без проверенного плана и осознанного согласия пользователя. Не запускать непроверенные UninstallString из реестра.
- Никаких «ускорителей» с бессмысленным убийством процессов, чисткой «RAM для галочки», отключением антивируса, античита, службы обновлений или изменением Realtime-приоритета.
- Оптимизация игры только opt-in, затрагивает **явно выбранные** пользовательские процессы, восстанавливает изменения после выхода из игры и закрытия органайзера; ошибка или недоступность прав не должны ломать систему.
- Автосортировка: сначала существующие папки/проекты, без перемещения внутренностей проектов, конфликтов, перезаписи; журнал операции + Undo; фоновые правила строже ручных.
- Вредоносность/PUA нельзя определять по одному издателю или названию; для угроз использовать Microsoft Defender либо проверенный антивирусный движок, показывать источник и достоверность результата.
- Для удаления ПО применять штатные деинсталляторы через подтверждённый UI; удаление остатков только после явной проверки, резервного/обратимого сценария и исключения общих библиотек.

## Контроль качества

Перед PR выполнить по возможности:
1. python -m compileall -q main.py core tests
2. python -m unittest discover -s tests -v
3. На Windows: реальная установка/обновление/удаление приложения и GUI self-test; проверка разных DPI/размеров окна, фонового режима и автозапуска.
4. Для оптимизатора: запуск и выход из реальной игры; неизменность системных служб; восстановление CPU-приоритетов; аварийное закрытие; нагрузка на игры/FPS/1% low; отсутствие лишнего опроса в фоне.
5. Для инвентаризации: локализованные пути, разрядности реестра, ограниченные права, проверка автозагрузки без опасных изменений.
6. CI на commit SHA в PR; не выдавать статус «готово», если тесты не запускались.

**Формат отчёта каждого работника в конце записи журнала:**

DIRECTION: цель и код задачи.
ACTION: конкретные действия.
FILES: изменённые файлы.
TEST: команды, результат и среда; отдельно то, что не проверено.
RESULT: подтверждённый результат, commit, ссылка на PR.
NEXT: следующие действия, риски и кому они доступны.

Запрещены фиктивные отчёты, заглушки вместо работающих кнопок и заявления о 100% готовности на основании плана.
